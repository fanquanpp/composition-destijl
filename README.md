# COMPOSITION — 一个风格派（De Stijl）平台跳跃游戏

用 three.js 写的完整平台跳跃游戏。整个世界按**风格派**（De Stijl / 荷兰风格派运动，Mondrian 与 van Doesburg 那一派）的规则构建：只有矩形、只有直线、只用红黄蓝三原色加白与黑，没有圆角、没有渐变、没有阴影、没有光照。

游戏本体是一个 3D 场景，但相机是**正交投影**——因为风格派是平的，而且正交相机让屏幕上的跳跃弧线和物理模拟中的弧线完全一致，跳跃距离可以精确判断。

```
    ┌──────────────────────────────────────────────────┐
    │ LEVEL I  │ ● COINS 12/37 │ ■ SCORE 1,486 │ TIME │  ← HUD 也是蒙德里安式的横条
    └──────────────────────────────────────────────────┘
         ████           ██████████            ██
         ████  ● ● ●    ██████████   ◆◆◆      ██  ███
    ────────────────────────────────────────────────────
```

## 快速开始

需要 Node 18+（只用来跑本地静态服务器，游戏本身不需要构建步骤）。

```bash
cd de-stijl-platformer
node tools/serve.mjs
# 打开 http://127.0.0.1:8080/
```

**必须通过 HTTP 打开**，不能直接双击 `index.html`。原因：项目用 ES modules + import map，且音频要通过 `decodeAudioData` 解码，`file://` 协议下都会被浏览器拦截。

也可以：

```bash
npm run serve        # 同上
npm run validate     # 校验三个关卡的几何与可达性（含 ASCII 地图）
npm run check-font   # 校验中文字体子集是否还能覆盖 UI 里所有字
npm run check        # 上面两条一起跑
npm run assets       # 重新下载素材并重裁中文字体子集
npm run serve:prefix # 按 /<repo>/ 子路径本地起服务，模拟 GitHub Pages
```

## 操作

| 按键 | 动作 |
| --- | --- |
| `A` `D` / `←` `→` | 左右移动 |
| `Space` / `W` / `↑` | 跳跃。按住跳得更高，早松手则是小跳；空中再按一次是二段跳 |
| `Shift` / `X` | 冲刺（短距离水平爆发，可跨过宽沟） |
| 鼠标 / `E` | 抓钩。朝准心射出，挂住方块后按住收绳摆荡，松手保留全部动量（仅第三关） |
| `Esc` / `P` | 暂停 · `R` 重开关卡 · `M` 静音 |

也支持手柄（左摇杆 + A/B）和触屏（自动出现虚拟按键）。

**规则**：蓝色方块（walker）和黄色方块（flyer）可以从上方踩死；黑色带刺的 spiker **不能踩**，碰到任何一面都扣血。尖刺扣一颗心，岩浆直接死亡。白旗是存档点，碰一下变红。

## 玩法内容

三个关卡，难度递进，共约 20 分钟：

| | 关卡 | 主题 | 引入的机制 |
| --- | --- | --- | --- |
| I | **PRIMARY FORMS** | 白底、三原色、一次一条线 | 跑跳、二段跳、踩敌、弹簧、单向平台、移动平台、尖刺、岩浆、存档点 |
| II | **THE GRID** | 竖线与线之间的空隙 | 贴墙滑行与蹬墙跳（爬竖井）、碎裂平台、飞行敌人、冲刺 |
| III | **BOOGIE WOOGIE** | 网格碎成节奏 | 全机制组合：岩浆海、连续蹬墙、抓钩摆荡、移动平台接力、画作画廊 |

关卡里还有两种「会响的」平台，都跟着生成式配乐走：

- **节奏平台**（白色板 + 蓝条）在节拍上循环：实心 3 拍 → 闪烁警告 1 拍 → 消失 1 拍。警告同时用三种方式表达：变黄、抖动、一排横杠一根根消失。只靠颜色的话色盲玩家看不见，只靠声音的话听障玩家听不见，所以形状也要说同一件事。
- **音阶条**（地面上的彩色嵌块）踩上去会响一个音。音高取自配乐**当前小节的和弦**，所以横着跑过去就是一串永远在调内的琶音，而且同一根条会随和声变化换音。

每关有：金币、计时与时间奖励、无死亡奖励、最佳分数/时间记录（localStorage）、关卡选择与解锁。

## 关卡怎么改

关卡是纯数据，`src/game/levels.js` 里没有一行 three.js 或 DOM 代码，所以可以在 Node 里直接跑校验。

坐标系：`x` 向右，`y` 向上，单位是格。矩形 `[x, y, w, h, color]` 的 `(x, y)` 是**左下角**。实体 `[x, y]` 的脚在 `(x + 0.5, y)`。

```js
solids: [
  [0, 0, 14, 2, 'white'],   // 底部 14×2 的白色平台
  [38, 2, 8, 2, 'yellow'],  // 一块黄色大板
],
oneWays:  [[64, 3, 4]],              // 可穿过的单向平台
movers:   [{ x: 47, y: 4, w: 3, axis: 'x', range: 4 }],
crumbles: [[15, 4, 2]],              // 踩上去会塌
springs:  [[19, 2]],                 // 弹簧
spikes:   [[33, 2, 3]],              // 3 格宽的尖刺
lava:     [[46, 0, 7, 1]],           // 岩浆
coins:    [[4, 4], [5, 5]],
enemies:  [{ type: 'walker', x: 10, y: 2, dir: -1 }],
checkpoints: [[40, 4]],
spawn: [2, 2],
goal:  [87, 2],
triggers: [{ x: 33, text: 'STOMP FROM ABOVE' }],  // 过某个 x 时弹出提示
paintings: [{ key: 'noIv', x: 30, y: 17, w: 6.4, h: 6.8 }],  // 背景里挂一幅画
```

改完跑一次校验：

```bash
npm run validate
```

它会输出一张 ASCII 地图（最快看清关卡长什么样）并检查：

- **硬错误**：颜色名拼错、两个矩形重叠（会产生共面 z-fighting）、实体埋在方块里、出生点/终点悬空、内容超出 `bounds`、**终点从出生点不可达**
- **可达性**：用 `config.js` 里真实的玩家参数建图，考虑跳跃高度、二段跳、弹簧加成、移动平台的整条路径、以及蹬墙竖井；弧线会被沿途的方块挡住
- **提示**：够不到的金币、永远走不到的敌人、悬空的弹簧、只靠冲刺才能过的沟

这套校验在开发中直接抓出了三个真问题：level 1 的柱子把终点封死、level 2 的竖井被顶盖封死且底部进不去、以及若干金币嵌在方块内部。

## 视觉是怎么做出来的

只有两条规则，`src/render/style.js` 实现了它们：

1. **一个立方体**。整个场景共用 `BoxGeometry(1,1,1)`，所有东西都是它缩放出来的。
2. **带黑框的矩形**。每个方块是两个盒子：一个黑色「框」比彩色面大一点点（每边 0.055 格）、但 z 方向略薄，彩色面盖住它的正面，于是只剩四周一圈黑边。两块相邻时，两条黑边会合成一条更粗的网格线——这正是蒙德里安画布的样子。

所以地形用**大矩形**而不是一格一格的小砖块：关卡数据本身就是大矩形，碰撞用的也是同一批矩形，不需要做任何合并。

**背景**是四层平面，正交相机没有透视，所以视差靠手动做：每层偏移 `相机位置 × (1 - closeness)`，`closeness = 0` 表示无限远（钉在屏幕上），`1` 表示跟着世界走。背景用的调色板是**褪色的**——每种颜色都往纸白方向混了 70% 左右，黑线变成暖灰。这样背景读起来像一张褪色的印刷品，而地形保持满饱和的三原色和纯黑边框，前后层次一目了然。（这一条是实机截图后才改的：最初的背景和地形一样饱和，红蓝大矩形看起来像能站的墙。）

**音乐**是生成的，不是素材：严格的 16 步网格，四条声部（贝斯、琶音、底鼓、军鼓/踩镲），每小节一个和弦，四小节循环，只有和声随关卡变化。音效优先播放下载的 CC0 采样，采样缺失时用振荡器合成兜底——所以删掉 `assets/audio/` 游戏照样有声音。

## 手感参数

全部集中在 `src/config.js`。模拟固定跑 1/120 秒一步，所以不同刷新率的机器手感完全一致（渲染、粒子、相机按帧走）。

```js
runSpeed: 9.6         jumpSpeed: 20.4       gravity: 62
gravityHold: 50       // 上升且按住跳时重力更小 → 满跳约 4.2 格
doubleJumpSpeed: 17.4 // 二段跳后总高约 6.9 格
coyoteTime: 0.10      jumpBuffer: 0.13      // 宽容输入
wallJumpX: 11.6       wallJumpY: 18.8       // 蹬墙跳
dashSpeed: 27         dashTime: 0.15        // 冲刺
```

跳跃弧线的**形状**和它的高度一样重要。重力分三段：上升且按住键时 ×0.82（所以按住键有意义）、接近顶点时 ×0.78（顶点滞空，这是「跳得舒服」的关键）、下落时 ×1.28 并且按 `(1 - (v/maxFall)²)` 逐渐收束到终端速度，而不是硬性截断。整套思路参考了 `speed-rouge` 的 `movement_core.gd`（见 `REFERENCE-REPOS.md`）。

另外两条来自同一处的手感规则：

- **动量是状态，不是上限**。超过跑速且仍在按同方向时，输入只以 0.55×重力 的速率**慢慢泄掉**多余速度，而不是把你拉回跑速——所以冲刺、弹簧、松绳之后的动量不会被摇杆一碰就没。
- **空中操控随速度衰减**：静止时满操控，达到跑速时只剩 45%。慢的时候灵敏，快的时候果断。

实机测得的弧线（每 40ms 采样一次高度，地面 y=2）：

- 单跳：峰值 4.19 格
- 二段跳：峰值 7.22 格
- 冲刺后按住前进：`vx` 从 27 以 34/s² 泄到跑速 9.6，耗时约 0.5 秒（改之前是立刻归零）

校验器里用的是保守值（只按 `gravity: 62` 算），所以实际能跳到的位置比校验通过的范围还宽松一点。

## 素材

第三方素材全部由 `tools/fetch-assets.mjs` 从原始公开来源下载，并在 `assets/CREDITS.md` 里逐条记录来源与许可：

- **three.js r186.1**（MIT）— 本地化到 `vendor/three/`
- **字体**（SIL OFL 1.1）：Archivo Black（标题）、Jost*（界面）、Space Mono（数字）、Noto Sans SC（中文，**按用到的字裁成的子集，173 KB**）
- **Piet Mondrian 画作 5 幅**（公有领域，来自 Wikimedia Commons）：标题画面、通关画面，以及挂在关卡背景里的画框
- **音效**（CC0，来自 OpenGameArt）：Deva 的《8-bit Sound Effect Pack Vol. 001》14 个采样，qhobbes 的落地音，artisticdude 的挥击声，rubberduck 的碎裂/落地声，以及这一轮为节奏平台和音阶条新增的 4 个：cemkalyoncu 的节拍器 `tick`、IgnasD 的 `Timetick`、BjarneK_92 的铃音（运行时按半音重新定调）、Hazmat Harry 的金属撞击

**关于字体**：专门查过有没有比 Jost 更「正宗」的风格派字体可用。结论是没有——van Doesburg 1919 年那套字母表没有任何 OFL/CC0/公有领域的复刻，能找到的 De Stijl 字体都是「仅限个人使用」。Jost 是 Futura（1927，包豪斯时期）的复刻，已经是许可干净的前提下历史最准确的选择，所以没有换。

重新下载：`npm run assets`（幂等，已存在的文件会跳过；`--force` 强制刷新）。下载脚本会校验文件头（TTF/JPG 魔数）、检查文件大小、失败自动重试，并在缩略图 400 时回退到原图。

**除上面这些以外，游戏里的一切——地形、角色、敌人、背景构图、UI、菜单、粒子——都是运行时用代码生成的**，没有一张位图贴图、没有精灵图、没有模型文件。

## 多语言（中文 / English）

界面支持中英双语。设置里可以选 **跟随系统 / English / 简体中文**，首次运行按浏览器语言自动判定，选择会存进存档。切换语言是即时的——当前正在看的那个界面会原地重绘，不用退出重进。

实现上有意分成两套查表：

- `t('hud.coins')` 管**界面文案**——短键、复用、稳定。
- `tSource('REACH THE COMPOSITION')` 管**内容文案**——也就是关卡名、副标题，以及关卡里飘出来的那些提示。它用英文原文当键，所以关卡数据完全不需要知道「语言」这回事，漏翻一句也只会退回英文，而不会露出一个生硬的键名。

两套都是「找不到就退回英文，再找不到就退回键本身」，任何一条缺失都不会把界面搞崩。现在两张表各 139 个键，另有 25 条内容文案。

**字体是这件事里最容易被忽略的坑**：Archivo Black、Jost、Space Mono 全都是纯拉丁字体，一个中文字形都没有。不换字体的话中文会掉到系统字体上，和周围排版完全脱节。所以新增了 Noto Sans SC，并把三个字体栈都改成「拉丁字体在前、中文字体在后」——浏览器是**逐字形**回退的，所以英文保留风格派的几何字形，中文走 Noto，两者在同一行里也不打架。

### 中文字体为什么要做子集

完整版 Noto Sans SC 是 **16.9 MB / 31036 字形**。放在磁盘上无所谓，放到网络上是要命的：先是慢，然后在连接不稳的时候**根本下不下来**——而字体下不来的后果是每个中文字都静默换成系统字体，整页排版崩掉。

这不是假设。部署到 GitHub Pages 之后实测：同一台机器上 629 KB 的图片能正常拉取，**17.7 MB 的字体连续四次重试全部失败**（连接被重置）。这个环境下大于十几 MB 的传输基本过不去——之前 `git push` 走 HTTPS 也是同样原因失败的。

所以 `tools/subset-font.py` 按**实际用到的字**裁出子集：**16.9 MB → 173 KB，小 99%**，并且保留可变字重轴，标题照样能压到很粗。整个 UI 只用了 490 个字符（其中 378 个汉字）。

子集只有一个失效方式，而且是**静默**的：以后新加的字不在子集里，浏览器悄悄换一个系统字体，一句话里出现两种字形。所以有 `tools/check-font.mjs` 把这件事挡住——它重新扫描 UI 源码、跟字体实际覆盖范围比对，缺字就**直接构建失败**并告诉你去跑 `npm run assets`。我把子集故意改坏试过，它确实会报错退出（exit 1）。

> 顺带一提，`speed-rouge` 里那个 Noto Sans SC 只有 1937 个字形，也是个子集，但只覆盖那个项目用到的字，所以没法直接拿来用。

## 无障碍与进度

**减少动态效果**：设置里有一个开关，首次运行时会读取系统的 `prefers-reduced-motion`。打开后关掉屏幕震动和速度变焦，粒子数量压到 35%，节奏平台仍然照常计时（那是玩法，不是装饰）。

**形状冗余**：节奏平台的警告同时用变色、抖动和横杠倒计时三种方式表达；奖牌的等级用「几格填满」表示而不是颜色。只靠颜色的话色盲玩家读不到，只靠声音的话听障玩家读不到。

**奖牌**：每关按自己的目标时间给金（70%）、银（100%）、铜（140%）三档，关卡选择界面用三个小方块表示。最佳分数、最佳时间、最多金币、最少死亡各自独立记录——速通和高完成度是两种成就，不该互相覆盖。

## 已知限制

- 浏览器切到后台时 `requestAnimationFrame` 会被节流，游戏画面会停住（回来会继续，不会快进——累加器有上限保护）。切换标签页时如果正在游戏中，`visibilitychange` 会尝试自动暂停，但某些内嵌浏览器面板不会触发该事件。
- 关卡 III 的竖井需要连续蹬墙跳，是本作最陡的一段难度曲线。
- 没有移动端布局专门适配：小屏上 HUD 会换行，触屏按键会覆盖底部。
- 中文字体是**按用到的字裁出的子集**（173 KB）。代价是：新增中文文案后必须重跑 `npm run assets` 重新裁一次，否则新字会掉回系统字体。这件事由 `npm run check-font` 拦截，不会静默上线。
- 裁子集用到 Python 的 `fonttools` + `brotli`。没装也不会坏——`npm run assets` 会退回直接使用 16.9 MB 完整版并在终端里警告，`check-font` 也会提示你体积异常。
- 只有一种中文（简繁合一），没有做繁体、日文、韩文。
- 没有音频文件时音乐会等到首次用户交互才开始（浏览器自动播放策略），这是预期行为。
